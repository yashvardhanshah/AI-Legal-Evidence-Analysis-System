# Phase 7 report design and access policy

Report requests reuse cookie authentication, CSRF and current case scope. Public registration cannot request a privileged role. Investigator/lawyer/administrator users with active-case write access may generate or annotate reports; approval/rejection additionally requires lawyer or administrator role. Authorized case readers may inspect/download completed reports, including after archival. All private routes recheck current case authorization, including job, version, PDF, snapshot, provenance and audit paths. No public report endpoint exists.

The existing PostgreSQL lease/advisory-lock/subprocess worker gains `--kind case_report` with its own heartbeat and least-mount report service. Case locks serialize version assignment and review decisions. A repeatable-read transaction captures case metadata, authorized participant names/roles, all evidence, latest completed OCR/NLP and vision runs per evidence, all completed case research runs, their exact inputs/source-linked judgment excerpts, existing human relevance notes, model provenance and source attribution. Failed/pending analyses are not presented as completed; coverage counts and missing-analysis notices explain omissions. Completed research with no sources retains its genuine insufficient-source outcome. No new retrieval, inference, source acquisition, statutory import or external summarization runs during reporting.

Original files and derived artifacts are SHA-256 verified. Page text/spans/entities must match independently retained extraction artifacts; visual source pixels/dimensions match their frame hash; bounding boxes and scores are validated. Saved judgment citations must match their actual SQL source records and original file hashes. Queries must match their recorded input spans. Inconsistencies fail closed. Snapshot JSON excludes storage keys and credentials. Report rendering escapes source/user text before ReportLab markup; it never fetches URLs, embeds scripts or executes source text.

Additive `0007_case_reports` creates `report_versions` and `report_reviews`, restrictive FKs, case-version/job-attempt uniqueness, completed-output constraints, an immutable-completed-version trigger and append-only review triggers. There is one terminal approved/rejected decision per version. Reviews record actual author ID/name/role, note, timestamp and both inspected hashes. A terminal decision cannot be rewritten or followed by another note; generate a new version for revisions. Completed PDF/snapshot metadata and bytes do not change when approved. No self-approval separation policy is claimed beyond the explicit lawyer/administrator permission. Audit events are retained for enqueue, retry, complete/failure, review and downloads/provenance access.

The PDF is permanently a **review copy**. It expressly requires externally verified approval metadata with matching hashes. It never calls an unapproved report a finalized investigation. This avoids a circular PDF hash and avoids silently changing an inspected document after approval. The API provides `review_status`, `is_approved` and `approval_embedded_in_pdf:false`. Human approval does not establish legal guilt, admissibility, statutory applicability or factual truth. Post-generation report notes/decisions remain in the external append-only history; captured Phase 6 human relevance annotations appear in the PDF as attributed interpretations.

Private content-addressed PDF/JSON files reuse `derived/` outside Git and are never statically exposed. APIs verify PDF and snapshot hashes before PDF download or review; snapshot/provenance reads verify canonical JSON against SQL and its private blob. Responses disable caching; downloads use fixed UUID filenames, nosniff and restrictive PDF CSP. Original mounts are read-only in the report worker; only derived output is writable. A lost lease cannot publish; failed attempts remain as separate versions and retries are capped at three. Worker deadlines, memory/CPU/process limits bound work. A crash between filesystem and SQL publication may leave a private unreferenced blob; no automatic deletion is performed.

Limits: 100 evidence files/case; 200 pages per included document; 10,000 entities/page; 300 sampled frames/visual run; 20,000 detections/frame; 100 research runs; 16 inputs/run; 100 source results/run and 100 annotations/result. Snapshot maximum 20 MB; PDF maximum 50 MB/2,000 pages; default worker deadline 600 seconds. Exceeding a limit fails instead of silently truncating sources. Global/per-user queue checks are application safeguards, not distributed quota guarantees. The generation snapshot records the actual source capture time, which can differ from enqueue time. A retry captures then-current sources and receives a new version; it does not rewrite a failed attempt.

ReportLab 5.0.1 (BSD) is pinned and hash-locked. Its bundled Bitstream Vera font is embedded under its bundled license; unsupported characters are visibly represented as Unicode code points in the PDF, and the downloadable JSON retains exact Unicode text. Complex-script shaping, PDF/A, digital signatures, malware scanning, a tamper-proof external ledger and production deployment are not claimed. Long source text flows across pages and no section is populated with invented material. Optional source-dependent sections are omitted when no genuine source exists. The legal limitation always states that verified statutory analysis is unavailable: BNS/BNSS/BSA/legacy imports remain zero.
